## 1. Overview

**Goal**: Compare parameter-efficient fine-tuning (PEFT) methods for plant leaf disease classification using EfficientNet-B0 as the backbone.

**Methods**: LoRA, QLoRA, QA-LoRA (V3 track) + Q/K LoRA (V1 track)

**Datasets**:
- **Train**: PlantVillage (54,306 RGB images, 38 classes, controlled lab photos)
- **Transfer test**: PlantDoc (real-world field images, 25 shared label mappings)

**Hardware target**: RTX 5060 with 8GB VRAM

**Workflow**:
```
download_assets.py → launcher_v3.py → launcher_test_v3.py → generate_dashboard.py → run_web_ui.py
```

## 4. Data Pipeline

### 4.1 Dataset Source
- **HuggingFace**: `plantvillage` dataset, `color` split
- **54,306 RGB images** across 38 classes
- **14 crop species**: Apple, Blueberry, Cherry, Corn, Grape, Orange, Peach, Bell Pepper, Potato, Raspberry, Soybean, Squash, Strawberry, Tomato

### 4.2 Split Strategy
```
PlantVillage (54,306 images)
├── HF color/train (80%) → split by leaf_id
│   ├── Train (85% of train) = 68% of total
│   └── Val (15% of train) = 12% of total
└── HF color/test (20%) = 20% of total
```

**Key detail**: Validation is created by `leaf_id` grouping, not raw image. This prevents leakage from multiple photos of the same physical leaf.

### 4.3 Data Transforms

**Training:**
```python
Resize(256)
RandomCrop(224)
RandomHorizontalFlip()
RandomRotation(±15°)
ColorJitter(brightness=0.2, contrast=0.2, saturation=0.2)
Normalize(mean=[0.485, 0.456, 0.406], std=[0.229, 0.224, 0.225])
```

**Validation/Test:**
```python
Resize(256)  # preserve aspect ratio
CenterCrop(224)
Normalize(mean=[0.485, 0.456, 0.406], std=[0.229, 0.224, 0.225])
```

### 4.4 Class Label Map
- Auto-generated by `get_data_loaders()` → `config/class_labels.json`
- Contains `num_classes` (38), `idx_to_class`, `class_to_idx`
- Must ship with checkpoints for inference

### 4.5 Data Loader
- File: `data/data_loader.py`
- Function: `get_data_loaders(config)` → returns `train_loader`, `val_loader`, `test_loader`, `class_names`
- Uses PyTorch `Dataset` and `DataLoader`
- Batch size: 32 (configurable)
- Workers: 4 (configurable)

## 5. Model Architecture

### 5.1 Backbone
- **EfficientNet-B0** (ImageNet pretrained)
- Loaded via `torchvision.models.efficientnet_b0(weights=None)` + manual state_dict from cached weights
- Feature extractor: `model.features` (MBConv blocks + final conv)
- Pooling: `model.avgpool` (global average pooling)
- **All backbone parameters frozen** — only PEFT adapters are trainable

### 5.2 Classifier Head
- File: `models/classifier.py` → `PlantDiseaseClassifier`
- Architecture: `Dropout(0.2)` → `Linear(1280, 38)`
- **No Softmax** — `CrossEntropyLoss` applies `log_softmax` internally
- Softmax applied externally at inference time in the evaluator

### 5.3 MBConv Block Structure
Each EfficientNet-B0 MBConv block contains:
1. **Expand Conv**: 1×1 pointwise (channel expansion)
2. **Depthwise Conv**: 3×3 (spatial features)
3. **Squeeze-and-Excitation (SE)**: Channel attention
4. **Project Conv**: 1×1 pointwise (channel reduction)

## 6. PEFT Methods

### 6.1 LoRA V3
- **File**: `models/peft/lora_v3.py`
- **Trainer**: `training/lora_trainer_v3.py`
- **Config**: `config/lora_config.yaml`
- **Paper**: Hu et al. 2021 (ICLR)

**How it works:**
- Freeze pretrained backbone
- For each target Conv2d with weight shape `(C_out, C_in, 1, 1)`:
  - Insert adapter matrices: `A` shape `(C_in, rank)`, `B` shape `(rank, C_out)`
  - Forward: `conv2d(x, W0 + (B @ A).view(C_out, C_in, 1, 1))`
  - Scaled by `alpha / rank`
- Merge support: `merge_lora_weights()` + `save_merged_model()` for zero-overhead inference

**Targets**: All non-depthwise Conv2d + `classifier.fc`
**Hyperparameters**: rank=8, alpha=16, dropout=0.1
**Trainable params**: ~193k
**Checkpoint**: ~18 MB

### 6.2 QLoRA V3
- **File**: `models/peft/qlora_v3.py`
- **Trainer**: `training/qlora_trainer_v3.py`
- **Config**: `config/qlora_config.yaml`
- **Paper**: Dettmers et al. 2023 (NeurIPS)

**How it works:**
- Quantize Q-path 1×1 conv weights to 4-bit NF4 using `bitsandbytes.functional.quantize_4bit(..., quant_type='nf4')`
- During forward: dequantize to bfloat16 → apply LoRA adapters → output
- Backbone frozen, only adapters trainable

**Targets**: Q-path pointwise convs + `features.8.0` + `classifier.fc`
**Quantization**: bitsandbytes NF4 (weight-only)
**Compute dtype**: bfloat16
**Trainable params**: ~193k
**Checkpoint**: ~7.6 MB

### 6.3 QA-LoRA V3
- **File**: `models/peft/qalora.py`
- **Trainer**: `training/qalora_trainer.py`
- **Config**: `config/qalora_config.yaml`
- **Paper**: Xu et al. 2024 (ICLR)

**How it works (Algorithm 1 from paper):**
1. **Group-wise INT8 quantization**: Split each output channel's weights into `L` groups, each with its own learned `scale` and `zero_point`. Weights stored as true INT8 integers.
2. **Grouped LoRA A**: Shape `(L, rank)` instead of `(D_in, rank)`. Input unfolded to patches, then `adaptive_avg_pool1d` reduces `D_in` to `L` groups.
3. **Standard LoRA B**: Shape `(C_out, rank)`, same as vanilla LoRA.
4. Does **not** use PEFT — `QALoRAConv2d` replaces `nn.Conv2d` directly.

**Targets**: Q-path pointwise convs + `features.8.0` + `classifier.fc`
**Quantization**: Group-wise INT8 (true integer, not fake-quant)
**Groups (L)**: 4
**Trainable params**: ~242k
**Checkpoint**: ~9.5 MB

### 6.4 Q/K LoRA (V1 — Legacy)
- **File**: `models/peft/qklora.py`
- **Trainer**: `training/qklora_trainer.py`
- **Config**: `config/qklora_config.yaml`

**How it works:**
- **Q-path** (Quantized): MBConv 1×1 convs → INT8 quantization + LoRA rank 16
- **K-path** (Kept FP32): SE layers (`fc1`/`fc2`) + `classifier.fc` → FP32 + LoRA rank 4
- Depthwise convs: frozen, no LoRA

**Naming**: Q = Quantized, K = Kept high-precision (not transformer Query/Key)
**Trainable params**: ~445k
**Checkpoint**: ~12 MB

### 6.5 Layer Target Summary

| Layer | LoRA V3 | QLoRA V3 | QA-LoRA V3 | Q/K LoRA |
|-------|---------|----------|------------|----------|
| MBConv expand 1×1 | ✅ adapter | ✅ NF4 + adapter | ✅ group-wise + adapter | ✅ INT8 + adapter |
| MBConv project 1×1 | ✅ adapter | ✅ NF4 + adapter | ✅ group-wise + adapter | ✅ INT8 + adapter |
| Head conv (`features.8.0`) | ✅ adapter | ✅ NF4 + adapter | ✅ group-wise + adapter | ❌ frozen |
| SE `fc1`/`fc2` | ❌ frozen | ❌ frozen | ❌ frozen | ✅ FP32 + adapter |
| Depthwise 3×3 | ❌ frozen | ❌ frozen | ❌ frozen | ❌ frozen |
| Stem (`features.0.0`) | ❌ frozen | ❌ frozen | ❌ frozen | ❌ frozen |
| `classifier.fc` | ✅ adapter | ✅ adapter | ✅ adapter | ✅ adapter |

**Interactive launchers:**
```powershell

```

### 7.2 Training Configuration

**Base hyperparameters** (`config/base_config_v3.yaml`):
| Parameter | Value |
|-----------|-------|
| Batch size | 32 |
| Epochs | 20 |
| Early stopping patience | 7 |
| Learning rate | 1e-4 |
| Weight decay | 1e-5 |
| Optimizer | AdamW |
| Scheduler | CosineAnnealingLR |
| Loss | CrossEntropyLoss |
| Mixed precision | FP16/BF16 (`torch.amp`) |
| Input resolution | 224×224 |

### 7.3 Training Loop

```
For each epoch:
  1. Train phase:
     a. Forward pass through model
     b. Calculate loss (CrossEntropyLoss)
     c. Backward pass
     d. Optimizer step (AdamW)
  2. Validation phase:
     a. Forward pass (no grad)
     b. Calculate validation accuracy
  3. Checkpoint logic:
     a. If val accuracy improved → save best checkpoint
     b. Always save last checkpoint
     c. Optionally save per-epoch checkpoint
  4. Early stopping:
     a. If no improvement for `patience` epochs → stop training
  5. Logging:
     a. Record loss, accuracy, LR, GPU memory per epoch
```

### 7.4 What Gets Saved

```
experiments/results/
├── checkpoints/
│   ├── <method>_best.pth      # Best validation accuracy
│   ├── <method>_last.pth      # Final epoch
│   └── <method>_latest.pth    # Most recent save
├── logs/
│   └── <method>_<timestamp>.log
├── plots/
│   ├── <method>_training_curves.png
│   ├── <method>_confusion_matrix.png
│   └── <method>_class_metrics.png
└── experiment_results.csv     # Summary row per method
```

## 8. Evaluation Pipeline

### 8.1 Evaluation Launchers

```powershell
py -3.11 launcher_test_v3.py    # V3 evaluation (recommended)
py -3.11 launcher_test.py       # V1 evaluation
py -3.11 eval_all_v3.py         # V3 batch evaluation
py -3.11 eval_plantdoc.py       # PlantDoc evaluation
```

### 8.2 Evaluation Flow

```
launcher_test_v3.py
  └→ get_data_loaders()
  └→ For each .pth in checkpoints/:
       └→ Trainer.load_checkpoint()
       └→ Evaluator.evaluate()
            └→ Returns y_true, y_pred, y_probs, class_names
       └→ metrics.calculate_metrics(...)
            └→ Multiclass: accuracy, precision, recall, F1 (macro)
            └→ Binary: accuracy, F1 (healthy vs diseased)
            └→ ROC AUC (One-vs-Rest)
            └→ Crop/disease correctness breakdown
  └→ Writes eval/<method>_checkpoint_ranking.csv
  └→ Writes per-sample confidence CSVs
```

### 8.3 Metrics Computed

| Metric | Description |
|--------|-------------|
| **Accuracy** | 38-class top-1 accuracy |
| **F1 Macro** | Macro-averaged F1 across 38 classes |
| **Precision Macro** | Macro-averaged precision |
| **Recall Macro** | Macro-averaged recall |
| **Binary Accuracy** | Healthy vs diseased (string match) |
| **Binary F1** | F1 for binary classification |
| **ROC AUC** | One-vs-Rest AUC from softmax probabilities |
| **both_correct_pct** | % where crop AND disease both correct |
| **name_only_correct_pct** | % where only crop name correct |
| **disease_only_correct_pct** | % where only disease correct |
| **none_correct_pct** | % where neither correct |

### 8.4 Output CSVs

**Per-method ranking** (`experiments/results/eval/<method>_checkpoint_ranking.csv`):
```
rank, checkpoint, size_mb, accuracy, f1_macro, binary_accuracy, binary_f1,
binary_roc_auc, both_correct_pct, name_only_correct_pct, ...
```

**Per-sample confidences** (`experiments/results/eval/<method>_<ckpt>_confidences.csv`):
```
image_path, true_label, pred_label, prob_0, prob_1, ..., prob_37
```

## 9. Cross-Method Ranking

### Script
```powershell
py -3.11 rank_experiments.py
```

### Inputs
- `experiments/results/experiment_results.csv`
- `experiments/results/eval/lora_checkpoint_ranking.csv`
- `experiments/results/eval/qlora_checkpoint_ranking.csv`
- `experiments/results/eval/qklora_checkpoint_ranking.csv`
- (V3 also includes QA-LoRA)

### Logic
1. For each method, pick the **best checkpoint** (rank=1 or `*_best.pth`)
2. Compare winners on a fixed scorecard:
   - Primary: `test_accuracy`
   - Tie-breakers: `f1_macro`, `binary_f1`, `peak_gpu_memory`, `trainable_parameters`
3. Assign overall rank (1 = best)

### Output
`experiments/results/eval/cross_method_ranking.csv`

## 14. Results Summary

### PlantVillage Test Set (10,735 images)

| Rank | Method | Accuracy | F1 Macro | Params | Size |
|------|--------|----------|----------|--------|------|
| 1 | **QA-LoRA V3** | **99.52%** | **0.993** | 242k | 9.5 MB |
| 2 | Q/K LoRA | 99.22% | 0.987 | 445k | 12.1 MB |
| 3 | QLoRA V3 | 98.91% | 0.984 | 193k | 7.6 MB |
| 4 | LoRA V3 | 98.89% | 0.984 | 193k | 18.1 MB |

### Key Findings

1. **QA-LoRA is the best overall method** — highest accuracy (99.52%) with moderate parameter count (242k)
2. **All four methods achieve >98.8% accuracy** — PEFT is highly effective for this task
3. **Quantization helps regularization** — quantized methods (QA-LoRA, Q/K LoRA) slightly outperform unquantized LoRA
4. **Group-wise quantization is superior to per-channel** — QA-LoRA's group-wise INT8 outperforms Q/K LoRA's per-channel INT8
5. **Smallest checkpoint is QLoRA** (7.6 MB) — best for resource-constrained deployment

### PlantDoc Transfer
Real-world field evaluation shows expected accuracy drop due to domain gap (lab vs field). Multiple mitigation strategies evaluated (segmentation, ensemble, style normalization, TTA).
